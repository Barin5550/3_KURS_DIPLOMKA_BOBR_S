# Маршрут — персональный план обучения

Курсовой проект по ПМ07 «Разработка мобильных приложений».
Тема: «Создание приложения для автоматического формирования персонального плана обучения».

Пользователь выбирает направление (Flutter, Python, английский язык, алгоритмы),
проходит диагностический тест и указывает, сколько часов в неделю готов заниматься,
в какие дни и к какому сроку. Приложение строит план по дням и перестраивает его,
если пользователь отстал.

Всё работает офлайн: облачные сервисы, ключи и регистрация на сторонних сайтах не нужны.

## Скачать

- **Android:** файл `marshrut-release.apk` на странице [Releases](https://github.com/Barin5550/3_KURS_DIPLOMKA_BOBR_S/releases).
  Откройте его на телефоне и разрешите установку из этого источника.
- **Windows:** архив `marshrut-windows.zip` там же. Распакуйте и запустите `marshrut.exe`.

Свежие сборки после каждого изменения лежат во вкладке
[Actions](https://github.com/Barin5550/3_KURS_DIPLOMKA_BOBR_S/actions) → последний запуск → Artifacts
(нужно войти в GitHub).

## Возможности

- Splash, регистрация с проверкой уникальности email, вход, автовход, выход.
- Онбординг: направление → тест → расписание → предпросмотр плана.
- Алгоритм: граф тем → исключение известных тем → сортировка Кана →
  раскладка по дням с лимитом часов → проверка дедлайна → интервальные повторения (+1, +3, +7 дней).
- Перепланирование при пропусках, несколько планов, свои темы, заметки, избранное.
- Pomodoro-таймер, статистика с графиками, история занятий.
- Ежедневные напоминания (Android, iOS), светлая и тёмная темы в тёмно-синем и оранжевом цветах.
- Профиль: редактирование, смена пароля, удаление аккаунта со всеми данными.
- Адаптивная вёрстка: телефон в обеих ориентациях и окно компьютера с боковой панелью.

## Стек

## Запуск

Нужен установленный Flutter SDK (проект собирался на Flutter 3.47.7, Dart 3.13.5).

```bash
flutter pub get
flutter run
```

### Android

Подключите телефон с включённой отладкой по USB или запустите эмулятор из Android Studio, затем:

```bash
flutter run                 # отладочный запуск
flutter build apk --release # готовый APK: build/app/outputs/flutter-apk/app-release.apk
```

APK для релиза подписывается отладочным ключом: для установки на свой телефон этого достаточно,
для публикации в Google Play нужен собственный ключ.

### Windows

Требования (см. [документацию Flutter для Windows](https://docs.flutter.dev/get-started/install/windows/desktop)):

1. Windows 10 или 11, 64 бит.
2. Flutter SDK и Git.
3. Visual Studio 2022 (именно Visual Studio, не VS Code) с набором
   «Разработка классических приложений на C++» (Desktop development with C++).
4. Режим разработчика Windows: Параметры → Конфиденциальность и защита →
   Для разработчиков → «Режим разработчика». Без него Flutter не соберёт проект с плагинами.

Проверка окружения и запуск:

```powershell
flutter doctor
flutter pub get
flutter run -d windows
```

Сборка готовой программы:

```powershell
flutter build windows --release
```

Программа появится в папке `build\windows\x64\runner\Release\`.
Запускается файл `marshrut.exe`; переносить нужно всю папку целиком, рядом с exe лежат нужные DLL и папка `data`.

База данных хранится в служебной папке пользователя (`%APPDATA%`), а не рядом с программой.
В Windows доступны мгновенные уведомления (окончание «помидора»); ежедневное напоминание
работает в версии для Android и iOS, потому что плагин уведомлений не умеет повторять
уведомление каждый день в Windows без установщика MSIX.

### Linux

Нужны пакеты для сборки GTK-приложений (`clang`, `cmake`, `ninja-build`, `pkg-config`, `libgtk-3-dev`):

```bash
flutter run -d linux
```

## Тесты

```bash
flutter analyze
flutter test                         # юнит- и виджет-тесты
flutter test integration_test -d linux   # или -d windows, или на устройстве Android
```

- `test/domain` — алгоритм: сортировка Кана, оценка знаний, раскладка, генератор, перепланирование.
- `test/core` — валидаторы, хэширование паролей, правило доступа к экранам.
- `test/data` — репозитории на SQLite в памяти и проверка JSON-каталога.
- `test/presentation` — экраны входа и регистрации, профиль, заметки, свои темы, «Мои планы»,
  статистика, Pomodoro, адаптивность и сквозной сценарий
  Splash → Регистрация → Вход → Главная → План → Профиль → Выход.
- `integration_test` — тот же сценарий в настоящем окне приложения.

Всего 97 модульных и виджет-тестов и интеграционный тест. Тест-кейсы и найденные ошибки описаны
в [docs/coursework/testing.md](docs/coursework/testing.md).

GitHub Actions ([.github/workflows/build.yml](.github/workflows/build.yml)) при каждой отправке кода
проверяет форматирование, запускает анализатор, все тесты и интеграционный тест в Linux,
затем собирает релизный APK и версию для Windows. Когда на странице Releases публикуется
новый релиз, файлы сборки прикладываются к нему автоматически.

## Скриншоты

Скриншоты всех экранов для отчёта генерируются автоматически: приложение
запускается с тестовыми данными и настоящими шрифтами Roboto.

```bash
flutter test tool/screenshots/screenshots_test.dart
```

Файлы появляются в `docs/coursework/screenshots/`.

Для проверки перед сдачей каждый экран можно снять в семи вариантах (светлая и тёмная тема,
маленький телефон, крупный шрифт, горизонтальная ориентация, окно компьютера):

```bash
flutter test tool/screenshots/qa_matrix_test.dart   # снимки в build/qa_screens/
```

## Курсовая работа

Готовый документ: [Курсовая_Маршрут.docx](docs/coursework/Курсовая_Маршрут.docx)
и [PDF](docs/coursework/Курсовая_Маршрут.pdf). Пометки `[ПРОВЕРИТЬ]` выделены жёлтым:
их нужно проверить перед сдачей (ведомство на титульном листе, стандарт списка литературы).

Документ собирается из Markdown-файлов `docs/coursework/*.md`:

```bash
python3 tool/coursework/build_coursework.py --pdf
```

Нужны pandoc, python-docx, Pillow и LibreOffice (для PDF). Чтобы перерисовать диаграммы Mermaid,
добавьте `--mmdc путь/к/mmdc` (пакет `@mermaid-js/mermaid-cli`).

Таблицы «критерий → где реализовано → как показать»:
[1 семестр](docs/criteria_semester1.md), [2 семестр](docs/criteria_semester2.md).
Отчёт для защиты, где по каждому критерию простыми словами сказано, что сделано и как это показать
(без путей к файлам): [Отчёт_по_критериям.docx](docs/Отчёт_по_критериям.docx)
и [PDF](docs/Отчёт_по_критериям.pdf), текст в [Отчёт_по_критериям.md](docs/Отчёт_по_критериям.md),
сборка `python3 tool/coursework/build_criteria_report.py --pdf`.

Памятка для подготовки к защите (идея, экраны, где что в коде, короткие ответы):
[Как_устроено_приложение.md](docs/Как_устроено_приложение.md), [DOCX](docs/Как_устроено_приложение.docx)
и [PDF](docs/Как_устроено_приложение.pdf), сборка `python3 tool/coursework/build_guide.py --pdf`.

Путеводитель по коду (что лежит в каждой папке и каждом файле, где искать каждую функцию):
[Путеводитель_по_коду.md](docs/Путеводитель_по_коду.md), [DOCX](docs/Путеводитель_по_коду.docx)
и [PDF](docs/Путеводитель_по_коду.pdf). Сам код прокомментирован по-русски: шапка каждого файла,
описание классов и методов, пояснения шагов внутри методов.

Иконки приложения для всех платформ генерируются скриптом `python3 tool/icons/generate_icons.py`.

## Структура

```
lib/
  core/          тема, роутер, валидаторы, хэширование, форматирование
  domain/        сущности, алгоритм планирования, интерфейсы репозиториев, сценарии
  data/          база drift, репозитории, каталог тем, уведомления
  presentation/  провайдеры Riverpod, экраны и виджеты
assets/catalog/  4 направления, 75 тем в JSON
docs/concept/    материалы защиты концепции (слайды, user flow, вайрфреймы, вопросы)
docs/coursework/ текст курсовой работы, скриншоты, диаграммы, итоговые DOCX и PDF
tool/            генераторы скриншотов, иконок и документа курсовой
```
