# ЗАКЛЮЧЕНИЕ

В ходе курсового проекта разработано мобильное приложение «Маршрут», которое автоматически формирует персональный план обучения по выбранному направлению с учётом знаний пользователя, его времени и срока и перестраивает план при отставании. Цель работы достигнута, все поставленные задачи решены.

1. **Проанализирована предметная область.** Рассмотрены трудности самостоятельного обучения, методика распределённого повторения по кривой забывания Эббингауза и техника Pomodoro. Показано, что план обучения удобно описывать графом тем с зависимостями, а порядок изучения находить топологической сортировкой.
2. **Рассмотрены особенности мобильных приложений и принципы их разработки:** ограниченные ресурсы устройства, работа без сети, безопасность данных, адаптивность интерфейса, разделение кода на слои.
3. **Проведён анализ аналогов.** roadmap.sh, Duolingo, Stepik, Coursera, Notion и Todoist закрывают задачу частично; ни одно решение не объединяет граф тем, учёт знаний, расписание под время и срок пользователя и автоматическую перестройку плана.
4. **Обоснован выбор технологий:** Flutter и Dart, чистая архитектура, Riverpod, собственный сервер REST API на Dart (shelf) с базой drift (SQLite), go_router, fl_chart, flutter_local_notifications, Material 3. Приложение работает с данными только через API и не зависит от облачных сервисов.
5. **Разработан алгоритм формирования плана.** Известные по тесту темы исключаются, остальные упорядочиваются алгоритмом Кана, раскладываются по учебным дням с дневным лимитом и дополняются повторениями через 1, 3 и 7 дней. Затем проверяется дедлайн, и при необходимости алгоритм подсказывает нужное число часов в неделю. Перепланирование сохраняет выполненное и раскладывает остаток заново. Алгоритм выделен в слой на чистом Dart и покрыт 32 модульными тестами.
6. **Спроектирован интерфейс и реализованы экраны:** заставка, регистрация, вход, главная, пять вкладок навигации, профиль, онбординг с диагностическим тестом, план, темы, статистика, заметки, Pomodoro, несколько планов. Интерфейс выполнен в стиле Material 3 в тёмно-синих и оранжевых цветах, есть тёмная тема, вёрстка адаптирована для телефона в обеих ориентациях и для окна компьютера.
7. **Приложение протестировано:** 137 модульных и виджет-тестов (в том числе тесты сервера и клиента API), интеграционный тест настоящего приложения с настоящим HTTP-сервером, 45 тест-кейсов, ручные проверки и матрица из 280 снимков экранов в светлой и тёмной теме, на разных размерах экрана и с крупным шрифтом. Найдено и исправлено 27 ошибок.
8. **Первая версия приложения проанализирована и доработана.** Хранение паролей переведено с однократного SHA-256 на PBKDF2-HMAC-SHA256 со 100 000 итераций с автоматическим пересчётом старых хэшей, добавлено удаление аккаунта, исправлена настройка уведомлений Android, сделаны иконка и название приложения. Сборка релизного APK для Android, версий для Windows и iPhone автоматизирована в GitHub Actions вместе с запуском всех тестов.
9. **Разработан сервер REST API, приложение переведено на работу с данными через API.** Сервер на Dart хранит данные в базе SQLite и предоставляет 39 адресов для получения, добавления, изменения и удаления данных. Вход выполняется по токену, сервер повторно проверяет данные и не даёт доступа к чужим записям, ошибки возвращаются кодами HTTP с понятным текстом. Приложение показывает пользователю ошибки сервера и связи и обновляет экраны после каждого изменения. Сервер запускается на ноутбуке, телефон подключается к нему по Wi-Fi.

**Практическая значимость.** Приложение можно использовать для реальной подготовки: в каталоге четыре направления (Flutter, Python, английский язык, алгоритмы), 75 тем с оценкой трудоёмкости, зависимостями и ссылками на материалы, а также 32 вопроса диагностического теста. Новое направление добавляется JSON-файлом без изменения кода.

**Направления развития:**

- резервное копирование базы сервера и экспорт плана в файл;
- адаптация интервалов повторения к результатам пользователя, например по алгоритму SuperMemo;
- редактор зависимостей тем и импорт собственных направлений;
- публикация в Google Play с собственным ключом подписи;
- размещение сервера API в интернете с шифрованием HTTPS, чтобы приложение работало вне локальной сети;
- публикация версии для iPhone в App Store с платным аккаунтом разработчика Apple.
