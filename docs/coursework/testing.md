# Тестирование приложения «Маршрут»

## 1. Подход к тестированию

Приложение проверяется на трёх уровнях, как рекомендует документация Flutter [25]:

1. **Модульные тесты** проверяют отдельные функции и классы без интерфейса: алгоритм построения плана, валидаторы, хэширование паролей, работу с базой данных.
2. **Виджет-тесты** запускают экраны или всё приложение в тестовой среде Flutter. База данных — настоящая SQLite в оперативной памяти, время зафиксировано (понедельник, 12.10.2026), уведомления заменены заглушкой. Так тесты не зависят от дня запуска и не трогают данные пользователя.
3. **Интеграционный тест** запускает настоящее приложение в окне операционной системы и проходит сценарий как пользователь [22].

Кроме автоматических тестов использовались ручные проверки: скриншоты всех экранов (генератор `tool/screenshots`), запуск настольной версии, сверка настроек проекта с документацией пакетов. Перед сдачей интерфейс проверен по матрице снимков (`tool/screenshots/qa_matrix_test.dart`): каждый экран снимается в семи вариантах — светлая и тёмная тема, телефон 393×851, маленький телефон 360×640, крупный системный шрифт (130 %), горизонтальная ориентация и окно 1280×800, у длинных экранов дополнительно снимается конец. Всего 280 снимков; ошибки вёрстки, которые сообщает Flutter, программа собирает в отдельный файл, а сами снимки просматриваются вручную.

Все тесты запускаются автоматически в GitHub Actions при каждой отправке кода (файл `.github/workflows/build.yml`): проверка форматирования, `flutter analyze`, `flutter test`, интеграционный тест в Linux на виртуальном экране, затем сборка APK и версии для Windows.
