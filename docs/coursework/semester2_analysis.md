# Анализ версии 1 семестра и план развития

## 1. Исходное состояние

К концу 1 семестра приложение «Маршрут» проходило весь демонстрационный сценарий из критериев: заставка, регистрация, вход, главная страница, навигация из пяти вкладок, профиль, основной раздел (создание плана: направление, диагностический тест, расписание, предпросмотр) и выход. Кроме обязательных экранов уже были заметки, собственные темы, избранное, несколько планов, перепланирование, статистика с графиками и таймер Pomodoro. Приложение запускалось на Android, Windows и Linux, проект содержал 79 автоматических тестов (см. `docs/criteria_semester1.md`).

В начале 2 семестра эта версия была проверена заново. Цель проверки — найти, что мешает пользоваться приложением на реальном телефоне и что не соответствует требованиям 2 семестра.

## 2. Как искали недостатки

1. **Сверка с критериями.** Критерии 2 семестра и требования к защите концепции прямо называют релизную сборку (.apk) и адаптивность интерфейса.
2. **Сверка с документацией пакетов.** Настройки Android-проекта сравнивались с README пакета flutter_local_notifications [27] (версия 22.3.1).
3. **Проверка безопасности.** Способ хранения паролей сравнивался с рекомендациями OWASP [35].
4. **Ручная проверка оформления.** Иконка, название приложения на телефоне, экран запуска.
5. **Новые автоматические тесты.** Для функций, которые раньше проверялись только открытием экрана, написаны тесты сценариев: создание, изменение и удаление данных через интерфейс.

## 3. Найденные недостатки

| № | Недостаток | Как выявлен | Чем грозит | Приоритет |
|---|---|---|---|---|
| 1 | Пароль хранился как однократный SHA-256 от соли и пароля | Сверка с рекомендациями OWASP [35] | SHA-256 считается очень быстро. Если файл базы скопируют с устройства, простые пароли можно подобрать перебором | Высокий |
| 2 | Не было удаления аккаунта | Проверка раздела «Профиль» | Пользователь не может удалить свои данные из приложения. Для приложений с регистрацией Google Play требует возможность удалить аккаунт [49] | Средний |
| 3 | В Android-проекте не хватало настроек для запланированных уведомлений: приёмников плагина, разрешения `RECEIVE_BOOT_COMPLETED`, desugaring | Сверка с документацией пакета [27] | По документации пакета без приёмников запланированное уведомление не показывается, а после перезагрузки телефона не восстанавливается. Ежедневное напоминание — одна из функций приложения | Высокий |
| 4 | Значок уведомления — цветная иконка приложения | Сверка с документацией пакета [27] | Android выводит в строке состояния только силуэт значка, поэтому вместо логотипа был бы белый квадрат | Низкий |
| 5 | Стандартная иконка Flutter и техническое имя «marshrut» под иконкой | Ручная проверка | Приложение выглядит незаконченным, его трудно найти среди других на телефоне | Средний |
| 6 | Не было релизной сборки APK | Сверка с критериями | Нельзя установить приложение на телефон без среды разработки. Релизная сборка — отдельное требование к защите | Высокий |
| 7 | Сборка и тесты запускались только вручную на одном компьютере | Анализ процесса разработки | Ошибку, которая проявляется только на чистой машине или на другой платформе, легко пропустить | Средний |
| 8 | Функции 2 семестра (заметки, свои темы, «Мои планы», статистика, Pomodoro) проверялись только тем, что экран открывается без ошибок | Анализ набора тестов | Ошибки в сценариях изменения данных оставались незамеченными. Новый тест сразу нашёл ошибку в диалоге переименования плана (ошибка № 12 в `testing.md`) | Средний |

## 5. Ограничения, оставленные на будущее

- **Сервер работает в локальной сети.** Данные хранятся на сервере API, который запускается на ноутбуке, поэтому телефон должен быть в той же сети Wi-Fi, что и ноутбук, а сервер — запущен. Запросы идут по HTTP без шифрования: для учебного проекта в домашней или учебной сети этого достаточно (п. 2.3.3). Направление развития — разместить сервер в интернете с доступом по HTTPS и добавить резервное копирование файла базы.
- **Число итераций PBKDF2.** OWASP для PBKDF2-HMAC-SHA256 рекомендует 600 000 итераций [35] (значение сверено с сайтом OWASP 11.10.2026). В приложении выбрано 100 000: на настольном компьютере (сборка Linux в режиме release) расчёт занимает около 0,4 с, на слабом телефоне он будет дольше [ПРОВЕРИТЬ время входа на телефоне]. Формат хэша позволяет поднять число итераций в следующей версии: старые хэши пересчитаются при входе.
- **Подпись релизной сборки.** APK подписывается отладочным ключом. Для установки на свой телефон этого достаточно, для публикации в Google Play нужен собственный ключ.
- **Напоминания в Windows.** Плагин уведомлений в Windows не умеет повторять уведомление каждый день без установщика MSIX, поэтому на компьютере доступны только мгновенные уведомления (окончание «помидора»).
- **iOS.** Сборка для iPhone делается в GitHub Actions без подписи и ставится через Sideloadly. Бесплатная подпись Apple действует 7 дней, после чего приложение нужно переустановить; публикация в App Store требует платного аккаунта разработчика Apple.
