# ПУТЕВОДИТЕЛЬ ПО КОДУ ПРИЛОЖЕНИЯ «МАРШРУТ»

Здесь описано, где что лежит в репозитории и за что отвечает каждая папка и каждый файл. Сам код подробно прокомментирован по-русски: в начале каждого файла сказано, за что он отвечает, у каждого класса и метода есть описание, а внутри методов пояснены шаги. Путеводитель помогает найти нужный файл, а комментарии в нём объясняют, как он работает.

## 1. С чего начать чтение

1. `lib/main.dart` — точка входа: открывает базу данных и настройки и запускает приложение.
2. `lib/app.dart` — корневой виджет: тема оформления, русский язык, роутер.
3. `lib/core/router/app_router.dart` — все экраны и правило, кого куда пускать без входа.
4. `lib/domain/planner/` — главный алгоритм: как из тем, теста и расписания получается план.
5. `lib/presentation/screens/` — экраны, по одной папке на раздел приложения.

## 3. Как связаны части: путь одного действия

Код разделён на три слоя. **presentation** (экраны и провайдеры) вызывает **domain** (сценарии и алгоритм), а domain работает с данными через интерфейсы, которые реализует слой **data** (база SQLite, настройки, уведомления). Провайдеры Riverpod в `lib/presentation/providers/providers.dart` создают все объекты и передают их экранам.

Пример: пользователь на шаге «Расписание» нажимает «Сформировать план».

1. `screens/onboarding/schedule_screen.dart` открывает предпросмотр (`/onboarding/preview`). Выбранные направление, ответы теста и расписание хранит `providers/onboarding_controller.dart`.
2. `screens/onboarding/preview_screen.dart` вызывает `PlanService.preview()` из `lib/domain/usecases/plan_service.dart`.
3. `PlanService` передаёт данные в `PlanGenerator.generate()` (`lib/domain/planner/plan_generator.dart`): исключение известных тем (`knowledge_estimator.dart`), порядок тем (`topological_sort.dart`), раскладка по дням (`scheduler.dart`), проверка дедлайна.
4. По кнопке «Начать обучение» вызывается `PlanService.createPlan()`, который сохраняет план через интерфейс `PlanRepository`; его реализация `lib/data/repositories/plan_repository_impl.dart` записывает план, темы и занятия в базу `lib/data/db/app_database.dart`.
5. Главный экран (`screens/home/home_screen.dart`) подписан на поток активного плана (`activePlanProvider`) и сразу показывает занятия на сегодня.

Так же устроены остальные действия: отметка занятия — `PlanService.toggleSession()`, кнопка «Перестроить» — `PlanService.replan()` и `lib/domain/planner/replanner.dart`, вход — `AuthController` и `AuthRepositoryImpl`.

### 4.4 `lib/domain/planner/` — алгоритм построения плана

Главная часть курсового проекта. Читать удобно в таком порядке: `plan_generator.dart` (общая схема из пяти шагов), затем каждый шаг по отдельности.

Таблица 5 — Алгоритм построения плана (папка lib/domain/planner/)

| Файл | За что отвечает |
|---|---|
| `plan_generator.dart` | Генератор плана из 5 шагов: исключить известные темы → сортировка Кана → раскладка по дням → проверка дедлайна. Если план не укладывается в дедлайн, перебором с шагом 0,5 ч подбирает нужное число часов в неделю. Главное: PlanGenerator, generate(), requiredHoursPerWeek(), lastStudyDate(). |
| `knowledge_estimator.dart` | По ответам диагностического теста определяет, какие темы пользователь уже знает. Верный ответ отмечает тему и всех её предшественников (обход графа через стек), неверный ответ снимает отметку с темы. Главное: KnowledgeEstimator, knownTopics(). |
| `topological_sort.dart` | Топологическая сортировка тем алгоритмом Кана: входящие степени, очередь с приоритетом по уровню и исходной позиции, обнаружение циклов. Главное: topologicalSort(), CycleDetectedException. |
| `scheduler.dart` | Раскладывает упорядоченные темы по календарю день за днём. В каждый учебный день действует лимит минут; сначала ставятся повторения, срок которых наступил, затем куски текущей темы (не короче 30 минут). После завершения темы планируются повторения через 1, 3 и 7 дней. Главное: Scheduler, schedule(), PendingReview, _numberParts(). |
| `replanner.dart` | Перестраивает план с сегодняшнего дня. Выполненные занятия остаются, остаток минут по темам раскладывается заново, просроченные повторения переносятся на сегодня, номера частей продолжают уже пройденные. Главное: Replanner, replan(), ReplanResult. |
| `dates.dart` | Функции для работы с датами без учёта времени суток, устойчивые к переходу на летнее время; ими пользуются планировщик, сервисы и экраны. Главное: dateOnly(), addDays(), daysBetween(), isSameDay(), countStudyDays(). |
